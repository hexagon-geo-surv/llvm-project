# AMDGPU test-triple migration helpers

These scripts assist the incremental migration of AMDGPU lit tests from the
old `-mtriple=amdgcn ... -mcpu=<gfx>` form to the new sub-architecture triple
form, e.g.

```
-mtriple=amdgcn-amd-amdhsa -mcpu=gfx900   ->   -mtriple=amdgpu9.00-amd-amdhsa
```

The `-mcpu` subtarget is folded into the triple's subarch field and dropped.
See `llvm/docs/AMDGPUUsage.rst` and the "AMDGPU: Introduce amdgpu triple arch"
change for background on the triple scheme.

## Scope

These helpers only rewrite the **command-line** form on `RUN:` lines. Tests
that select the target through the IR (a `target triple` directive or a
`"target-cpu"` function attribute) are out of scope and left untouched.

## Files

- `amdgpu-migrate-test-triples.py` — the rewriter. Operates on a list of test
  files and edits their `RUN:` lines in place. Conservative: it only rewrites a
  line that has exactly one `-mtriple=amdgcn*` token and exactly one
  `-mcpu=<cpu>` token naming a plain gfx target (or a known device alias).
  Feature-suffixed CPUs (`gfx900:xnack+`), generic targets (`gfx9-generic`),
  and lines with multiple triple/cpu tokens are skipped. Pass `--dry-run` to
  list files that would change without writing.

- `amdgpu-migrate-test-triples-batch.sh` — drives one reviewable batch:
  rewrites a list of files, runs `llvm-lit` on the ones that changed, and
  reverts any file that fails so only passing migrations remain staged.

## Why lit is the safety net

Folding the CPU into the triple yields byte-identical codegen *except* where
the triple string itself is emitted into output (the `.amdgcn_target`
assembler directive and the `amdhsa.target` metadata field). A small number of
tests CHECK those strings and will fail after rewrite; the batch driver reverts
them automatically so they can be regenerated by hand in a follow-up.

## Typical usage

```sh
# From the llvm-project repo root, with a build in build_rel_with_debinfo.

# 1. Enumerate candidates (files whose RUN lines would actually change):
grep -rlE 'RUN:.*-mtriple=amdgcn' \
  llvm/test/CodeGen/AMDGPU llvm/test/Analysis llvm/test/Transforms \
  | sort > /tmp/all.txt
llvm/utils/amdgpu-migrate-test-triples.py --dry-run $(cat /tmp/all.txt) \
  > /tmp/candidates.txt

# 2. Slice ~100 logically-related files into a batch list, then:
llvm/utils/amdgpu-migrate-test-triples-batch.sh /tmp/batch00.txt

# 3. Review `git diff`, then commit the batch.
```

## Updating the CPU tables

The gfx-name and alias tables in `amdgpu-migrate-test-triples.py` are derived
from `llvm/include/llvm/TargetParser/AMDGPUTargetParser.def`. If new GPUs are
added there, extend the `GFX` and `ALIASES` tables to match.
